# codex-cmd-trace

Go + Fyne 单窗口工具，监听 Codex 本地会话 JSONL，展示命令及其对应输出。深色半透明网格背景、青色命令和快速逐字动画。无原生标题栏，顶部使用与命令相同的等宽字体，显示 Codex Command Trace、置顶图钉和退出按钮。Windows 拖动使用固定的屏幕坐标抓取点，避免窗口内部坐标变化造成抖动；图钉可切换置顶并前置窗口。这些原生窗口操作目前仅适配 Windows。

Windows 窗口宽度约为主屏幕的四分之一，高度为宽度的 16/9，尺寸固定；屏幕高度不足时按比例缩小。窗口外框与命令卡片使用相同的描边。命令卡片随逐字输入和输出展开自然增高，短输出不预留空行；长输出达到上限后保留中间五行和上下各一行渐隐的上下文，平滑滚到末尾。到底后底部完全显示，顶部仍保留渐隐。所有滚动条隐藏，仍可在输出区域用滚轮回看。新的命令置于顶部，结果更新保留原卡片位置；不提供自动滚动开关或清空按钮。

输出每约 75 毫秒追加一行，追加时平滑增加卡片高度或滚动，不会一次性展示全部结果。播放动画与日志接收解耦。失败命令与 FAILED 标签使用同一种红色。Windows 窗口实际裁切为圆角，半径与卡片统一为 10 个界面单位。完整的 sessions 目录绝对路径位于应用名称下方，作为 subtitle 自动换行，不截断；顶部增加深色半透明遮罩，底部不再有路径区，上下使用一致的外边距。

窗口仅保留最新 20 张命令卡片。更早的卡片、动画和待返回结果引用会一起清理，旧结果迟到不会重新插入历史。Windows 启动时自动显示并前置窗口，但不会自动开启永久置顶；需要时可点击图钉。

图钉旁的四格图标切换独立窗口模式，默认关闭。开启前已有卡片仍留在主窗口；开启后每条新命令使用一个无额外按钮的独立窗口，复用同一个 card 控件，保留输入、输出动画与点击详情行为。窗口从主窗口所在显示器开始，自上而下填满一列，再向右换列，然后使用其他显示器的工作区，避开主窗口与任务栏。窗口随内容增高而重新排布，空间不足时淘汰最旧独立卡片，仍遵守最近 20 条的历史上限。

关闭模式时，独立窗口逐个淡出、关闭，保留的卡片按新旧顺序恢复到主窗口。关闭过程中收到的新命令直接进入主窗口；快速重新开启也不会把已有卡片再次转换。主窗口退出会清理全部独立窗口。此定位后端目前适配 Windows，多显示器布局包含不同缩放比例、负坐标屏幕与镜像屏幕去重；其他平台会保持开关关闭并提示尚未适配。

点击命令卡片可打开详情窗口，展示完整命令和全部已接收输出，不受主卡片行数上限或播放动画限制。命令尚未返回时显示等待状态，返回后自动更新。详情宽度为主窗口两倍，高度为主窗口减去当前 header 高度；重复点击复用同一个详情窗口。详情顶部可关闭或复制命令与输出，关闭主窗口会同时关闭详情。

Windows 上，详情窗口根据主窗口所在显示器的工作区选择左侧或右侧，优先完整放入空余区域；两侧都不足时保持在屏幕内并尽量减少重叠，不改变主窗口位置。详情还展示日志中可确认的会话名称、会话 ID、工作目录、客户端版本、模型提供方、Git 信息、日志文件、完整调用 ID、调用与返回时间，以及退出码、耗时、后台进程编号等结果元数据。原始调用输入可展开查看，未提供的信息不编造。

长日志卡片最多排版最近 16 行及约 8 KB 的尾部文字，单行也有预览长度上限，避免随日志增长重复排版全部内容；完整结果保留在详情与复制功能中。置顶激活状态使用深色前景图标搭配青色背景。

subtitle 使用紧凑的 2 单位行间距，并移除了路径文本控件额外的内边距。

## 启动

本机 Windows 已配置项目专用的便携 C 编译器，启动脚本会自动使用，不修改全局 PATH：

```powershell
.\run.ps1
.\run.ps1 -Demo        # 播放演示，不执行任何命令、不监听真实日志
.\run.ps1 -Cli         # 保留原控制台模式
```

演示模式包含五条命令，覆盖短输出、测试结果、长构建输出和失败状态。

演示卡片标记为“演示”；subtitle 路径仍是配置的日志目录，但演示模式不监听该目录。正常启动不带 `-demo` 即进入真实监听。

也可直接运行已构建的 `codex-cmd-trace-gui.exe`，无需安装编译器。点击右上角的 × 退出，关闭窗口即停止监听。

其他开发环境需要 Go 和 C 编译器，参见 [Fyne 环境准备](https://docs.fyne.io/started/quick/)。Windows、macOS、Linux 使用同一套 Fyne 界面；各平台需安装相应图形开发依赖，本次只在 Windows 实际验证。窗口级透明度目前仅 Windows 适配，其他平台保留深色面板风格。

```powershell
go run .              # GUI
go run . -cli         # 控制台
go run . -history
go run . -dir C:\path\to\sessions -interval 3s
```

默认监听 `$CODEX_HOME/sessions`，未设置时使用用户目录下 `.codex/sessions`。默认从现有文件末尾开始，只展示启动后的调用；新文件从头读取。使用 `-history` 可读取全部历史。

如果日志目录的同级 `session_index.jsonl` 中存在对应会话的 `thread_name`，命令卡片会显示名称标签；缺失时省略，不用日志文件名假装会话名称。

目录事件触发增量读取，每 3 秒扫描补查。支持新建子目录、文件截短或替换、跨写入的半行 JSON；按日志文件和调用 ID 关联结果。Ctrl+C 停止。

支持 `exec_command`、`shell_command`、`shell`、`exec` 和 `write_stdin`。直接显示命令、显式指定的工作目录、成功或失败状态、耗时和输出。桌面版 `exec` 中的常见字符串参数可直接提取，不执行包装代码；不含命令的包装调用自动隐藏，动态参数暂无法还原。

连续 `text(await tools.NAME(...))` 的顺序调用逐条配对展示，中间非命令工具的返回也计入位置，但不展示。仅在完整输出数量与调用数量一致时建立对应；并行、条件分支、额外输出或缺失返回等无法确认的结构退回整组展示并提示，不猜测关联。短编号用于关联调用组与结果。

监听与解析在同一生产端串行处理，产生结构化 `commandEvent`，通过容量为 256 的 `chan` 交给控制台或 Fyne 消费者。配对结果提供独立命令和输出字段；GUI 通过 `fyne.Do` 调度到界面线程，打字动画按 Unicode 字符推进，输出等待命令动画结束后展开。GUI 使用完整日志路径与调用 ID 关联卡片，短编号仅用于展示。窗口关闭会取消监听和后台动画。

输出可见时机取决于 Codex 写入日志的时机；“执行中”表示返回了后台进程会话，后续 `write_stdin` 按进程会话编号展示。启动前已开始的调用，其结果默认不会展示。

当前为小规模原型：事件发生时扫描目录元数据，但只读取新增字节；大量历史文件时后续可优化索引。日志及命令输出可能包含敏感信息，请注意终端内容。

## Windows 自动打包

推送任意 tag 后，GitHub Actions 自动运行测试并打包 Windows x64 程序。例如：

```powershell
git tag v0.1.0
git push origin v0.1.0
```

在仓库 [Actions](https://github.com/dongfg/codex-cmd-trace/actions) 中打开对应的 `Package Windows` 运行记录，在 Artifacts 下载打包结果。产物保留 30 天，包含版本 ZIP，内有 `CodexCommandTrace.exe`、本文档和程序 SHA256 校验值。解压后直接运行 EXE；构建时静态链接编译器运行库，无需另行安装 Go 或 GCC。

目前仅打包 Windows amd64，不自动创建 GitHub Release。普通分支推送不会触发打包。
